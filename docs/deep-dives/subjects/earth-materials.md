## First game's proposed ladder: Sand Table

**Fun action:** make a mound, remove a scoop, watch it settle and reshape it. **Purpose:** early spatial cause/effect; later material movement and controlled comparison. The proposal is one family of modes, not a promise that every band needs every rung.

### A small inspectable dry model

Definition candidate: 12 broad columns, each with capacity eight grain tokens. A tap on a large tray region adds one short batch of three grains above the chosen column; tokens then fall and settle. Existing grains never vanish. Adjacent columns relax when their height difference exceeds one: move the top grain from the higher to the lower, using a fixed scan/tie order until stable. This is an invented two-dimensional toy model, not a measured angle of repose. Overflow goes into a visible return tray; Scoop moves up to three tokens from the selected column back to the hopper, and all may be poured again. Empty scoop/pour actions are neutral. A full hopper is not a collectible resource or a wait: Return all restores the same round instantly.

Prove finite termination and deterministic replay in the eventual definition: falling lowers height; each relaxation reduces the sum of squared column heights; cap input and process the short event queue before accepting the next batch. Reset/resize/cancellation must neither duplicate nor lose tokens. The first implementation may use broad three-column bays instead of twelve individually tappable columns so every target remains at least 100 units in both views. No small cell is an input target. Define queued-touch feedback explicitly; silent ignored touches are not acceptable.

| Proposed rung | First complete round and new decision | Finish / meaningful future property |
| --- | --- | --- |
| **1: Make a mound** · L/T | One tray; first tap anywhere pours into its central bay. Further taps repeat; optional large Scoop removes some | Finish appears after one player-caused visible change; no requirement for a precise shape or number of taps. Conservation includes hopper + surface + return tray |
| **2: Two little hills** · T/P | Two broad bays; choose where to pour or scoop, with tap alternatives for both | Any changed landscape can finish. Side preference never counts as a miss; both bay actions leave a recoverable state |

| **5: Same breeze, one change** · S | Run the bare baseline, then choose one of two covers on an identical mound; equal authored breeze in each | Check which visible run moved fewer grains; ties accepted if generated. Exploration is free, comparator uses transported solids, not water volume |
| **6: Keep a path, build a dune** · U/G horizon | Choose two interventions to retain a marked path while depositing enough grains at a dune marker | Enumerate every successful plan; ordinary completion accepts all, no least-cost gate. Define transport/cover semantics and prove solvability before implementation |

**Accounting and support:** rungs 1–3 have no wrong choices or counted hints. Their completion must not be reported as independent mastery or automatically treated as two smooth skill rounds; define creative-mode adaptation before registration. In rungs 4–6, running/replaying/resetting an experiment or revising a plan is free. Only an explicit incorrect Check counts a miss: gentle boing, spoken explanation based on the actual trace, then after two misses a useful glow counted once for that decision. Requested help explains one observation, then demonstrates an action; assisted completion remains available and earns the ordinary one sticker. Freeze hint counts, retry boundaries and supported Finish in the definition, rather than inheriting another game's scoring.

**Future checks:** seeded conservation, bounds, deterministic settling and finite completion; all reachable scoop/return states recoverable; compare claim evaluator with actual trace; exhaustively enumerate later plan solutions and useful repairs. First build: typecheck/units, filtered first/last-round play, ghost finger and one portrait review; shared-file changes add build. These are future checks, not checks run here.

## Outcrop Detective: one older and parent case

First case avoids faults and fossils: a fictional cliff with bottom dotted layer A, middle striped layer B, top pebbled layer C, and a dark intrusion X that cuts A/B but stops below C. The game discloses that the deposited layers started horizontal and were not overturned. A/B/C are pattern names, not mineral IDs or ages in years.

Four large event cards: deposit A, deposit B, intrude X, deposit C. Constraints: A before B, B before X (X cuts it), X before C (C covers the intrusion). Accept A→B→X→C and render exactly those relations. First exploration allows any ordering and replay; impossible histories receive an explanatory preview, with no miss until Check. Help highlights one cut or covering contact; later assistance places one justified relation and labels it helped. One accepted, possibly helped ribbon completes the round. The preview must model intrusion through already existing layers, not let magma know which later layer to avoid.

**Deeper ambiguity case:** X cuts A but does not intersect B laterally; C covers both. The authored observation mask hides the relevant X/B contact. Then both A→B→X→C and A→X→B→C can fit. Accept both as possible histories; ask whether their relative order is known, accepting “not enough evidence.” The useful next observation reveals an X/B contact that was genuinely hidden. Enumerate all 24 permutations against the disclosed observations; never reject a history for disagreeing with the author's preferred story. Numerical ages, fault order, erosion/unconformities and fossil correlation come only after separately reviewed definitions.

This differs from Story Steps/Timeline Trail through generating and inspecting a geological cross-section, not merely arranging an authored story. If that renderer/evidence interaction does not earn its scope, keep the case as a Timeline Trail content packet instead. M/G appeal remains a person check; a solver proves consistency, not enjoyment or geologic truth.

## Experience and presentation

Sand Table opens with one broad warm-sand tray and a visible hopper. First touch compresses the pour pad and makes a soft granular synthesized sound; the grain shower starts immediately. Use palette colors, Graphics/optional code-rendered texture, pentatonic pitched sounds and subdued non-pitched grain noise. No imported sprites or recordings. A bottom-left pet stays clear of both tray and controls; view-based portrait reflow stacks the scoop/return/finish controls without shrinking them. Never require shaking the iPad, exact swipes or two fingers.

Replay varies mound placement and original tray outlines, then sediment origins and interventions; it adds choices rather than particle clutter or speed. Outcrop uses patterns plus speech, a selected-event editor and an expandable cross-section so four event cards do not become tiny handles. Every instruction and evidence explanation needs replayable `ctx.instruct`/`ctx.say` content and a how-to ghost finger through the actual inputs. Finish uses the shell once; no local collection reward.

Co-play: maker and observer swap after one visible change; a child can describe by pointing. Proposed off-screen companion: make a *paper* layer picture and cover one edge to compare what can still be known. It is not released instruction yet. Real sand/soil, specimens, outdoor visits and tools retain the repository's named practical-safety reviewer dependency; no home excavation or collecting advice is supplied by this study.
