# Device check, 2026-11-28

The first twice-weekly phone and controller check. There was no rotation yet, so this run took Today's six and 15 games with changes merged in the last four days (new levels, Stir and See, pad pointer work), then wrote [ROTATION.md](ROTATION.md).

**How it ran:** headless Chromium (Playwright) against the dev server. Each game played into level 1 and its newest level in four setups: phone upright (390×844, touch, with a 47 px notch and 34 px home bar simulated through the safe-area variables), phone sideways (844×390, touch, 47 px side insets), laptop (1440×900, mouse) and gamepad (1440×900, a stubbed standard-mapping pad read through `navigator.getGamepads`). The script checked that every touch target is on screen, clear of the notch and home bar, and at least 40 px on a phone. It also flagged text under 12 px, page and console errors, and on the pad setup that the hand appears, A sends a press, Start pauses and resumes, and which targets arrow jumps reach. This is not a real phone or controller.

**Frame rate:** not measurable here. Headless Chromium draws with software GL, so even a light screen ran 6–13 fps under 4× CPU throttling. That number says nothing about a phone.
