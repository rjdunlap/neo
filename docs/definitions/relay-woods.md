## Taps, recovery, accounting and supported completion

Use `onTap`; entire stump/friend responds with immediate press bounce. Holder, receiver badge, speech replay, background, stale input, cancellation/outside release and taps during flight/feedback never count as wrong. Decorative edges, glows and moving message have no input. A tap becomes at most one transition; lock route taps for the0.4s hop (reduced motion shows immediate transfer) and feedback, then reopen through scene-owned scheduling. Keep one holder; message never teleports because of a second tap.

Every distinct **open adjacent** friend is an accepted hop, including backtracking and revisits. This refines the study's “some valid route”: an open completion walk may retrace; no hidden visited-node ban or trap at the log. At1 the forward next carrier nods; returning toward S is accepted exploration. At2 every open walk arriving at R finishes, including loops: do not grade efficient routing there. At3 choosing the clear or blocked arm is an experiment, not wrong until deliberately tapping across its visible log. From that arm, walk back through S or use Start over.

Unjoined friend: at1 shrug and “Not next yet”, no miss; two such taps trigger help. At2–4 one miss per deliberate unjoined tap, gentle boing and “Those friends have no path between them.” Log crossing at3 similarly adds one miss, points at log and says “That path is blocked. Try a clear path.” Holder stays put in both cases. Never count the accepted visit to a blocked arm as a miss. Cumulative round errors persist across reset/retry.

At4 every open hop is allowed while exploring. Keep `hopsTaken` and the full traversed ribbon; at R compare to `d(S,R)` in the open graph. If larger: one miss for that arrival, show actual and minimum hop ribbons side by side, “That was three hops. There is a way with two. Try again.” Then return picture to S and clear only route/hop state. Count all retracing hops. Never give one miss per long-path hop, reject the first longer-branch tap, finish the long delivery or change graph/message on retry. Correct minimum arrival finishes. Simple routes longer than the minimum are not the only possible wrong arrivals: loops also count once at arrival.

Start over is a separate100-unit control at every level; it returns holder to S and clears hop ribbon without changing seed, picture, errors or help. It costs no miss/hint and is never required for recovery at1–3. No Undo or extra save architecture needed.

Help is capped at **one per round**, since there is one route task. Set assisted flag before any answer-revealing glow, manual hint or bot-supported finish. Repeated help/retry never adds a second hint or clears it. Automatic help after two errors (at1, two unjoined explorations) and manual Hint use the same flag. Glows are noninteractive and retarget from the new holder after a hop; never leave a stale suggested friend lit. Keep requesting help/retrying available. Ordinary repeat instruction and non-answer feedback do not count as help. At1 forward nod is entry guidance, while the two-tap answer glow records1 as decided October23. No mastery inference from a miss-free cause/effect round; shell adaptation remains unchanged: helped rounds are not smooth; four misses can still be struggling despite the1-hint cap.

BFS hint from current holder uses **open** graph. At1–3 choose an adjacent node whose receiver distance decreases; at the blocked endpoint this properly points back along the branch. Never name the holder, blocked edge or a screen-nearest decoy. At4 compute `hopsTaken + d(holder,R)`: if equal to original optimum, glow a decreasing-distance next node; if greater, explain “Let's start again for fewer hops” and glow Start over. Next hint may demonstrate that reset, then route normally. A further help request can run ghost-finger taps to completion; mark assisted first and never call finish directly. Stable ID tie-break selects one BFS next node, but all permitted alternatives remain accepted.
